# dots 桌面界面

一个窗口装下 `dots` 的全部日常操作：看它在干什么、给它派活、批准它想做的事、跟它说话。
不用开终端，不用背命令。

![主界面](desktop/01-main.png)

---

## 打开

**装了安装包**：双击开始菜单或桌面上的 `dots`。

**在仓库里开发**：

```bash
cd desktop && npm start
```

第一次打开时后端要导入依赖，**顶栏会显示「正在启动后端…」约 10 秒**。这期间所有按钮是灰的 ——
不是卡住，是后端还没开始读输入，这时候发的命令会在它准备好的那一刻一起涌进去，顺序会乱。
等它变成「值守中」再动手。

---

## 界面分五段

从上到下：**顶栏 → 待批横幅 → 目标 / 技能 / 活动 → 对话 → 命令抽屉**。

### 顶栏

`● 值守中  每 60s 一轮  [停止]`

那个「每 60s 一轮」就是它「主动」的节拍：每隔这么久，它自己去翻一遍事件源（工作区的新文件、
邮箱、日历），有东西就自己建目标、自己干。点「停止」它就歇着，点「开始值守」再跑起来。

停止**不是立刻的** —— 它可能正跑着一个目标。按钮会一直显示「停止」，直到后端推来
`loop_stopped` 才算真停。急着关窗口也没事，它会把没跑完的目标放回队列。

### 待批横幅

只有**它停下来等你**的时候才出现，是整个界面唯一用琥珀色的地方：

> ⚠ a7f3 想发邮件给 alice：「周会改到周四」　[批准] [拒绝]

它按 `dot.toml` 里的 `[approval.rules]` 决定哪些动作要问过你。没写到的动作一律 **ask**（默认从严）。
挂着不批的话，默认 72 小时后自动按**拒绝**处理 —— 一个永远等不到回复的审批，就是一个悄悄卡死的目标。

### 目标

它干过的和正在干的活，每行是：编号、状态、目标原文、结论、证据、花了多少 token、多久以前。

状态有七种：`待批准`（它自己派生出来的，要你点头）、`排队中`、`在跑`、`停下等你`、
`待复核`、`完成`、`失败`。

**「待复核」值得单说**：它说完成了但**没给证据**（工作区路径、邮件 id、URL）时会落到这里 ——
没人能核对一个没有证据的结论。

### 技能

它干活时自己攒下来的可复用流程，也存在工作区里，是普通 markdown 文件。

技能库是**渐进披露**的：只有「名字 + 一句话描述」会进它的系统提示，正文等真用到时才去读。
所以描述被限制在 60 字符 —— 超出的部分每轮都会被截断，等于没写。

### 活动

完整流水：什么时候收了事件、建了目标、被哪条规则拦下、什么时候跑完。
出问题时先看这里。

### 对话

**直接打字就是跟它说话**，它记得上下文，能接着追问。

对话和后台目标是**两条线**：聊天不占目标队列，后台 tick 也不碰它。要让一件事在后台慢慢跑，
用「新建目标」。

## 命令抽屉：每条命令都是一个按钮

![命令抽屉](desktop/02-drawer.png)

界面底部那一条「▴ 全部命令」，点开是 `dots` 的全部子命令，**按钮上写的是中文**，不写
`init`、`doctor` 这种原始命令名。**鼠标停上去会告诉你它到底干什么**，顺带把对应的
`dots xxx` 写出来。

窗口太矮时抽屉会自动收起，保证上面的内容不被挤没。展开状态记在本地，下次打开还是那样。

有些命令需要参数（新建目标、学习、看技能…），点了会弹一个小输入框。
**会删改文件的三条**（删技能、整理技能、生成全局配置）会再问一次。

`serve` 不在里面 —— 常驻循环由顶栏那个按钮管，不需要你手动起。

| 分组 | 按钮 | 实际命令 |
|---|---|---|
| 配置 | 生成配置 / 生成全局配置 | `dots init` / `dots init --global` |
| 配置 | 体检 / 自检 | `dots doctor` / `dots selftest` |
| 目标 | 新建目标 | 原生 `goal`（不走 CLI） |
| 目标 | 跑一轮 / 全部目标 / 活动日志 | `dots tick` / `ls` / `log` |
| 审批 | 批准 / 拒绝 | `dots approve <编号>` / `reject <编号>` |
| 技能 | 学习 / 技能库 / 整理技能 | `dots learn` / `skills` / `curate` |
| 技能 | 看技能 / 删技能 | `dots skill show <名>` / `skill rm <名>` |
| 成本 | 用量 | `dots cost` |

### 命令跑起来的样子

点「体检」这类命令，**输出面板会从底部升起**，内容是流式出来的，跑完显示退出码：

![输出面板](desktop/03-output.png)

「自检」要跑 30 秒，所以不能等它跑完才显示。输出面板可以复制，也可以关掉。
命令之间是**排队**的 —— 一条在跑的时候点下一条，它会在后面等着。

## 和它说话

![对话](desktop/04-chat.png)

它用的是同一个大脑、同一个工作区。你在聊天里让它读文件、查资料、写东西，它会真的动手，
不是只描述打算怎么做。

**聊天里它想做 `ask` 类动作时会当场问你**，不走待批队列：

![审批确认](desktop/05-ask.png)

这里是真事：让它发邮件，它调了 `send_email`，后端把请求推给界面，弹这个框等你的决定。
点「拒绝」，它会照做并且**记住** —— 同一件事再让它做，它会引用规则告诉你「被拒了不要重试」。

（如果这个框弹出来时你已经离开超过 10 分钟，点「批准」会提示你**审批已经过期**，
agent 那边早就按拒绝处理了 —— 界面不会因为请求发出去了就假装成功。）

## 数据放在哪

跟配置文件同目录。默认那份在 `~/.dots/`：

```
~/.dots/
├── dot.toml          配置（密钥只写环境变量名，不写进这里）
├── dot.db            目标、事件、审批、活动流水
└── workspace/        它的工作区 = 沙箱
    ├── inbox/        往里扔文件，它下一轮自己会发现
    ├── skills/       它攒的技能
    └── ...
```

想换个地方，改 `dot.toml` 里的 `workspace` 和 `db`。

## 已知限制

- **后端启动要等 10 秒左右**（要导入 langchain 那一整串）。这期间界面只能显示「正在启动后端…」。
- **聊天不是流式的**：慢模型下只有「正在想…」三个字，可能要等十几秒。
- **命令不能中断**：跑起来只能等，或者关窗口。没有取消按钮。
- **目标列表和活动各只显示最近 60 条**，多了会静默截断。
- 装完之后如果模型报错说找不到 key，那是**密钥要走系统环境变量**（比如 `DEEPSEEK_API_KEY`）——
  从开始菜单启动时，进程继承的是系统环境，不是你在终端里 export 的那个。
